## 5. 我判定的部分（每条附理由，可一句话推翻）

### 5.1 桌面 hover：**扶正 + 抬升 + 阴影加重**
- 动作：`rotate → 0`、`translateY(-6px)`、`scale(1.03)`、阴影加深；约 180ms。
- 理由：卡片本身是**倾斜贴着**的，"扶正"是它最自然的反馈（像从墙上把照片拿起来看）；
  laya 那两个选项（只放大 / 只加阴影）在倾斜卡片上几乎看不出变化。
- 只在 `@media (hover:hover)` 生效，触屏不触发。
- ⚠️ **一个张力要记明**：卡片**不可点**，但 hover 动画天然暗示"可以点"。
  处理：**光标保持 `cursor:default`**（绝不改 `pointer`），让动效读作"照片浮起来"而不是"点我"。
  若作者觉得误导，删掉这一条即可（图纸只说"有 hover 动画"，没说必须保留）。

### 5.2 题注字体：**首页专用的手写体字体**（可换成作者手写 PNG）
- 做法：在 `index.html` 单独加一条 Google Fonts 手写体 link（如 `Caveat`），**只影响首页**
  （这块 panel 也只在首页），不动其余 391 个页面；字体栈尾部接站内已有的 `LXGW WenKai` 与 `cursive` 兜底。
- 理由：图纸明确要"中性笔手写感"，英文手写感站内**没有**现成字体；"CSS 斜体假装手写"一眼就假。
- **升级路径已留好**：日后若作者逐条手写并给 PNG 字条，把 `.larry-pola-cap` 的文字换成 `<img>` 即可，结构不用改。

### 5.3 金色底
`color-mix(in srgb, var(--larry-gold) 18%, #fff)` ≈ `#f5efe4`，复用既有 token；可加**极轻**中央提亮（只为把视线收到照片区）。

### 5.4 相框蓝绿：固定种子的伪随机 + 相邻必不同色 + 蓝绿各半
用固定种子的 LCG 生成序列，再扫一遍把 `seq[i] === seq[i-1]` 的翻掉。种子固定 ⇒ 每次渲染颜色一致（不刷新一次换一次）。
**不允许相邻同色**：两块同色并排会在轨道上连成一大片色块，把逐张翻看的节奏压塌。

### 5.5 纹身装饰：底部一条带，且只当纹理
整层 `opacity:.12`（≤0.14 硬约束内）、统一染金（`mask` + `background-color`）。
素材管线复用已跑通的 M76 线稿抠图流水线。

### 5.6 其余
| 项 | 决定 | 理由 |
|---|---|---|
| 桌面倾斜角 | 固定角度表（如 `+11° / -5° / +8° / -9°` 循环）＋固定垂直偏移表 | 图纸是"每张不一样"；用**固定表**而不是 `Math.random()`，避免刷新一次排布全变 |
| 箭头步长 | 每次 1 张（吸附） | "滚动"语义 |
| 循环 | 克隆一套接尾 + 越缝无过渡跳回 | 两端都不出空档 |
| 引擎 | **一个索引 + 一个轨道**，桌面/移动只差 step / 旋转 / z-index | 避免两套翻页逻辑 |
| 语言 | **原生 JS 零 jQuery** | demo 壳无 jQuery（已查证）；线上有 jQuery 也照跑 |
| 长 lore 文案的归宿 | 可见题注用**短词**；**长 lore 句进卡片的 `alt`/`aria-label`**（不可见但保留内容与无障碍） | 图纸要短词，但 12 条 lore 是站内已有内容，不该丢 |

## 7. 几何与数值（按图纸换算，已验算高度够用）

**卡片结构**（自内向外）
```
图像区 3:4  →  白边：上/左/右 6%卡宽  →  下白边 20%卡宽（放题注）
整卡比例 ≈ 宽:高 = 1 : 1.43
```

**桌面 1440×720**
- 内容宽 ≈ 1325（stage 左右各 4% 内边距）
- 4 张 + 3×26px 间距 → 卡宽 **312**，卡高 ≈ **446**
- 含 ±10° 倾斜的包围盒高 ≈ **485**；面板可用高（扣标题/按钮）≈ **540** ✓

**移动 390×390**
- 内容宽 ≈ 351
- 中心卡宽 ≈ **38%** = 133 → 卡高 ≈ **190**
- 两张侧卡：旋转 **±20°**、水平偏移 **±0.5 卡宽**、垂直下移 8%
- 扇形总跨 ≈ **322** ≤ 351 ✓；扇形包围盒高 ≈ **223**，可用高 ≈ **265** ✓
- 三个数值都是 CSS 变量（`--pola-fan-r` / `--pola-fan-x` / `--pola-fan-y`），图纸若想更开或更收，改一个数

## 9. 素材交付规格

**竖版照片**
- 图像区 **3:4 竖版**；两人保不住时退路是放宽到 **4:5**；
- 长边 **1200px** 足够（桌面卡宽 312、图像区约 275×367）；
- 命名 `pola-NN.jpg`（两位序号，与题注表顺序一致），放 `images/gfx/larry-anniv-2026/`；
- **必须 `git add`**（否则线上 404）。

**题注**（每条）
```js
{ img: "…/pola-01.jpg", cap: "Love you!", capZh: "爱你！", alt: "（长 lore 句，进 alt 不可见）" }
```
- `cap` 是**可见的短词**（中性笔手写感），示例见图纸：`"Love you!"`、`"Gotcha !"`；
- `capZh` 是中文短词（站内双语约定）；
- `alt` 放长 lore 句（保留内容 + 无障碍）。

**纹身装饰**：白底线稿或照片都行，走 M76 管线；成品透明 PNG（黑线 + alpha，上色由 CSS `mask` 完成）。

**唯一替换点**：`docs/demo/js/larry-anniv.js` 顶部的 `POLAROIDS` 数组 —— 换照片 = 只改数组 + 放文件。
数组为空时面板降级为金色底 + CTA，不报错、无 404。

## 16. v1.3.1：移动端由"淡入淡出"改成真正的"翻卡片"

**作者反馈**：中间卡往左滑应**盖到左边那张上面**、左边那张被盖下去后消失；右边卡应**连贯地移到中间**；
「这应该是翻卡片的效果，而不是淡入淡出的效果」。

### 16.1 原来的问题
进出的卡用 `opacity` 做显隐 ⇒ 新卡从右边**淡入**、旧卡往左**淡出**，看起来是渐变而不是卡片在移动。

### 16.2 改法：用**几何 + 层叠**取代透明度
- **全场 `opacity` 恒为 1**，不再有任何透明度渐变（过渡只保留 `transform` 与 `box-shadow`）。
- 深层的卡**直接叠在槽位后面**：同一槽位、同一个旋转角，只比槽位多出 **2px**（`deep` 封顶 3 ⇒ 最多 2px/4px 两条叠边），
  层叠 `z = 100 - deep`。于是：
  - 中间卡往左 → `z=99`，旧左槽卡降到 `98` ⇒ **中间卡盖在它上面**，旧卡被盖住；
  - 右边槽位那张整段位移到中间、`z=100` 升到最高 ⇒ **连贯移动**，不是淡入；
  - 新露出的一张本来就是右侧槽位后面那 2px 处的卡 ⇒ **钻出来**，也不需要淡入。
- 移动端只把 **`|d| > 4`** 的卡隐藏并关过渡（模运算窗口在边界会把 `d` 从 −21 绕到 +19；
  阈值取 4 而不是 2 是因为 `|d|=3/4` 的卡与槽位同位，显示那一刻不会弹跳）。
- 桌面端也一并去掉了透明度显隐（4 张铺满、`d=4` 的卡本来就在视口外被裁掉），
  现在进出场是**从右边缘滑进来**，同样是连续位移。

### 16.3 验证（新增 9 项翻卡专项断言，与面板 20 项合计 **29/29**，0 console error）

| 断言 | 实测 |
|---|---|
| 所有卡片 `opacity` 恒为 1（无淡入淡出） | 非 1 的张数 **0**（翻页前后各查一次） |
| 过渡是连续位移、非瞬移（取 4 帧采样） | x：**162 → 135 → 128 → 126**（单调左移） |
| 原中间那张 → 左槽，且 z 高于原左槽那张（盖住它） | 中间 → `d=-1 z=99`；旧左 `z=98` ✓ |
| 原右槽那张 → 中间，且 z 最高 | 右 → `d=0 z=100` ✓ |
| 旧左槽那张同槽但 z 更低（被压到下一层） | `d=-1 px=-2px z=98` ✓ |
| 三个槽位 z：中间 100 > 左右槽 99（左右同层） | `-1:99  0:100  1:99` ✓ |
| 可见形状恰好 3 个（+ 2px/4px 叠边） | `0\|0px  1\|0px  1\|2px  1\|4px  -1\|-4px  -1\|-2px  -1\|0px` ✓ |

### 17.2 翻卡动效精进（作者："要抬起再落下，考虑真实物理"）
参考开源实现后采用四条手法（零依赖，仍是纯 CSS/原生 JS）：
1. **抬起→落下的弧线**：注册 `@property --lift`（未注册的自定义属性不能被 keyframes 插值），

2. **弹簧缓动**：主过渡改 `cubic-bezier(.34,1.56,.64,1)`（开源卡片组常用曲线），末段轻微过冲使落位更自然

3. **抬起时轻微放大 + 旋转过冲**：`@property --pop`（缩放）与 `--over`（角度）随同一关键帧动画，
   过冲方向 = 行进方向（往左甩就再往左多转 5° 再收回）；阴影同时加深变大（离桌面更高的线索）；
4. **手势改用 Pointer Events**（原为只监听 touch）⇒ 单套代码同时覆盖触摸 / 鼠标 / 触控笔，**桌面也能拖**；
   配合 `touch-action:pan-y` + `overscroll-behavior-x:contain`（真机左右都能翻的根因就是原先 `touch-action:auto`
   被浏览器滚动手势接管）。

**为何"只能往左翻"**：代码本身左右对称（实测左滑→下一张、右滑→上一张、绕回末张都对），
真机失效是浏览器接管了横向手势；已由 `touch-action:pan-y` + Pointer Events 修掉。
